# Question set

One question per message, each with your recommendation inside it, so the team can
say "yes" or correct you. `you decide` is a real answer and is final.

Four questions in the default mode. Seven in `detailed`. Everything not asked, you
decide and write down with a reason.

Skip any question the code already answers.

## Default mode: the four only the team can answer

### 1. Who is looking at it, and what are they doing?

The one that sets the register. A shift supervisor checking a list at 6am, a student
comparing three options, and a caseworker filing a claim want different interfaces,
and none of them wants to be delighted.

Recommendation to offer: from the audience and the moment of use, name a register in
one word and say why. `Utilitarian` for a tool used under time pressure,
`institutional` for something that has to look accountable, `friendly` for a
consumer product people return to, `craft` for anything whose value is the making.

What it sets: type class, color intensity, radius, and how much chrome the screens can
carry.

### 2. Show me an interface you find easy to look at, and one you find hard.

The highest-value question in the set, and the one people find easiest. Reactions are
reliable where adjectives are not. Ask for products they already use, not design
references from a gallery.

Recommendation to offer: name the two or three properties you can actually extract
from their examples (density, type weight, amount of color, how much chrome), and
check them back. "You picked a tool with almost no borders and one green accent. That
is what you are reacting to."

What it sets: the calibration for every later judgement, including yours.

### 3. How much does one screen have to hold?

Density decides the spacing ladder, the type scale step for body text, and whether a
card is a container or a table row. An app showing one number per screen and an app
showing forty rows are different visual systems, not different skins.

Recommendation to offer: from the busiest screen in the inventory, pick `comfortable`
(few items, one idea per block, generous space) or `compact` (many items, scan first,
tighter rhythm), and name which screen forced the choice.

What it sets: the spacing ladder and the type scale ratio.

### 4. Corners, borders, or shadows?

This one question sets the whole geometry and people have opinions about it
immediately. Sharp and bordered reads precise and institutional. Rounded and shadowed
reads soft and consumer. Flat with hairlines reads editorial or technical.

Recommendation to offer: one of the three, tied to the register from question 1, with
a radius scale to go with it. Then give the rule that keeps it consistent: pick one
and use it everywhere, because a rounded card next to a square one looks like a
mistake rather than a choice.

What it sets: radius, border versus shadow, and how depth is expressed.

## Detailed mode: three more

### 5. What should the type do?

Two decisions, not one: the class of typeface and the job it does. A grotesque reads
neutral and technical, a humanist sans reads approachable, a serif reads institutional
or editorial, a mono reads exact.

Recommendation to offer: from the register, name one class and one weight strategy.
"One family, two weights, no italics" is the safest default, and say what it would
cost to change later.

### 6. What is color for here?

Color needs a job or it becomes decoration. The jobs that survive are: mark one
primary action, show state, carry identity, or separate regions. At most two.

Recommendation to offer: one accent with one job, a neutral scale, and a status set
used only for status. Name the failure explicitly: three accents means none of them
means anything.

### 7. What is the one thing that must feel like us?

The signature motif: the thing a classmate would recognize in a screenshot. It can be
a numbered index, a hairline rule, a monospace label, a colored left edge, an oversized
numeral, a dotted field. One thing, applied consistently.

Recommendation to offer: propose one motif drawn from the product's domain or from the
register, and name the screen where it will be most visible.

## What to write down after each answer

Keep a running list in the conversation, one line per decision, with the reason:

```text
Register: utilitarian, because the supervisor reads it at 6am, one handed.
Density: compact, because the rota screen shows 14 rows.
Geometry: borders and small radius, because it reads precise rather than soft.
Type: one grotesque, two weights, because the register is technical.
Color: one accent for the primary action only, status colors for state only.
Motif: the time, set in mono at the left of every row.
```

Every line becomes a section of `design.md`. A line with no reason is not a decision
yet, and it will be the first one a teammate overrules.
